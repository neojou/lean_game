# use

## 概述

目標是「存在某個東西滿足性質」時，用 `use` 提出**見證**（你認為存在的那個值）。

本遊戲裡最常見的就是不等式：`a ≤ b` **定義成** `∃ c, b = a + c`，所以證 `≤` 幾乎總是先 `use` 一個差。

本遊戲的 `use` **不會**自動接著 `rfl`，提出見證後還要自己把剩下的等式證完。

## 示例

### 1. 存在量詞 `∃ n, P n`

若目標是 `∃ n : ℕ, n + 0 = n`，可以：

```lean
use 0
```

目標會變成 `0 + 0 = 0`，再用 `rw [add_zero]` 與 `rfl`（或視情況 `exact`）收掉。

### 2. 不等式 `a ≤ b`（本關最常用）

`a ≤ b` 就是「存在 `c` 使得 `b = a + c`」。官方解答裡有兩種典型寫法：

已經知道差是 `e + 1` 時：

```lean
use e + 1
rw [succ_eq_add_one, add_assoc]
rfl
```

差剛好是 `1` 時（例如從 `d` 走到 `succ d`）：

```lean
use 1
exact succ_eq_add_one d
```

差是假設裡的變數 `a` 時，直接：

```lean
use a
```

然後用 `rw` / `exact` 對齊等式。

### 3. `use` 一個複合項

見證不必是單一數字，可以是算式：

```lean
use e + 1
```

Lean 會把目標改成證明 `succ d = d + (e + 1)` 這類等式（實際形狀依當下 hyps 而定）。

### 4. 選錯見證會卡住

若 `use` 了對不上的數字，目標會變成一個**假的等式**，後面怎麼 `rw` 都證不出來。這時用「復原一步」換一個見證，不要硬堆 tactic。

## 細節

- 語法：`use t`，其中 `t` 是一個項（數字、變數、`e + 1`…）。
- 對應的數學動作：告訴 Lean「我選這個當存在量詞的例子」。
- 若目標不是 `∃` 也不是 `≤`（展開後的 `∃`），`use` 會失敗。

## 本遊戲的實作

比 Mathlib 的 `use` 弱：提出見證後**不會**自動 `rfl`。這是刻意的，讓你看清楚「選見證」和「證等式」是兩步。
